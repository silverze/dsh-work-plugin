# 周报 / 项目周报

目标：让读者在 3 分钟内知道“发生了什么、偏没偏、下一步怎么办”。

## 输入

确认：汇报周期、汇报对象（团队/管理层/客户）、材料范围（飞书文档/表格/聊天记录/附件）、必须包含的指标、篇幅。默认 1 页 A4。

## 结构

1. **本周结论**：3 条以内，直接给判断（达成/风险/需决策）。
2. **关键进展**：按项目或工作流分组；每条写“做了什么 → 结果 → 证据”。
3. **数据**：核心指标表（目标/实际/完成率/环比），注明口径与时间。
4. **风险与阻塞**：影响、概率、需要的支持、责任人。
5. **下周计划**：3–5 项，写清交付物与时间点。
6. **需决策**：需要谁在什么时候决定什么。

## 流程

1. 先读材料，列出事实清单；缺数据时明确标注“待补”，不要猜。
2. 按“结论先行”组织，不按时间流水账。
3. 每个进展项标注来源（文档名/表格/会议）。
4. 用 `skill(office-docx)` 生成 docx；需要时用 `skill(office-render)` 检查版式。
5. 用 `present` 交付，附一句“数据口径/未完成项”的说明。

## 质量门槛

- 数字与源表一致；口径、单位、时间范围写清。
- 不用“持续推进”“赋能”等空话；每句话可被验证。
- 区分“已完成 / 进行中 / 未开始 / 阻塞”。
- 不在周报里加入未经确认的承诺。
- 默认 1 页；超出时先删重复信息，不删风险。

## 边界

- 不把聊天中的猜测写成事实；标注“待确认”。
- 不自动发群或写入飞书，除非用户确认。

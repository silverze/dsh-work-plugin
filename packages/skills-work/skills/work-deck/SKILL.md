# 汇报 PPT

目标：一页一个观点，观众能顺着标题读完整个故事。

## 输入

确认：受众（管理层/客户/团队）、时长、页数上限、品牌模板、必须包含的数据与结论。默认 10–15 页、20 分钟。

## 结构

1. 封面（主题、汇报人、日期）
2. 执行摘要（3–5 条结论）
3. 背景与目标（为什么现在做）
4. 3–5 个发现/方案页（每页一个 takeaway 作标题）
5. 数据页（1–3 页，图表 + 一句结论）
6. 风险与权衡
7. 下一步与资源诉求
8. 附录（明细、来源）

## 流程

1. 先写 **outline**（每页标题 + 一句结论），给用户确认后再做视觉。
2. 用 `skill(office-pptx)` 生成；套用用户模板；统一字体、配色、页脚。
3. 图表用源数据重绘，不截图模糊图；标注单位与来源。
4. 用 `skill(office-render)` 渲染成图片，逐页检查溢出、遮挡、错位。
5. 用 `present` 交付 pptx，并说明“哪些页需要人工补数据”。

## 质量门槛

- 标题是结论，不是“背景介绍”“数据分析”这类目录词。
- 每页不超过 6 行正文；能图不表，能表不字。
- 数字与源报告一致；来源写在页脚。
- 不超过页数上限；超了先删重复页，不删风险页。
- 视觉检查通过：无文字溢出、无图片拉伸、无字体缺失。

## 边界

- 不虚构数据、客户 logo、引用；需要授权素材时向用户要。
- 不自动上传或分享，除非用户确认目标文件夹/群。

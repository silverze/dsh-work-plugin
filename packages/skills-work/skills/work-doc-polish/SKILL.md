# 文档打磨

目标：在不改变事实的前提下，让文档更清楚、更短、更像目标读者会读的东西。

## 输入

确认：原文、目标读者、用途、语气（正式/简洁/亲和）、篇幅、必须保留的术语/数字/引用。缺失时先问一个最关键的问题。

## 流程

1. 读全文，标出：核心论点、重复、跳跃、歧义、事实/数字、必须保留的原文。
2. 先改结构（段落顺序、标题层级），再改句子，最后改措辞。
3. 逐段改写：一段一个意思；主动语态；删形容词堆砌；统一术语。
4. 对照检查：事实、数字、引用、承诺是否被改动；改了就标出来。
5. 生成 `changes.md`：改了什么、为什么、哪些地方需要作者确认。
6. 用 `skill(office-docx)` 输出 docx（或 md）；`present` 交付。

## 质量门槛

- 不新增未经原文支持的事实、数字、引用。
- 不改变原意；不确定的地方保留原句并标注。
- 术语全文一致；同一概念不换三种说法。
- 长度符合目标；压缩时先删重复和空话，不删限定条件。
- 标题能独立表达观点；段落首句是主题句。

## 输出

1. 修订稿（docx/md）
2. `changes.md`：结构性修改、逐段修改、待确认项
3. 一句话说明“这版最适合谁读”

## 边界

- 不代替作者做事实判断；涉及合规/对外口径时提示人工复核。
- 不自动发布或发送。
